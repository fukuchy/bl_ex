# バトルライン ISMCTS エージェント 仕様書（v1）

作成日: 2026-10-07

## 1. 目的と範囲

学習を用いない SO-ISMCTS（Single Observer Information Set MCTS, Cowling et al. 2012）で着手を決めるバトルラインのエージェントを定める。後の Oracle Guiding や AlphaZero 型（方策・価値ネットワーク＋ISMCTS）への拡張の土台と、比較のベースラインを兼ねる。

この文書が扱うのは ISMCTS 探索部分のみである。ゲームエンジンと評価（対戦・計測）は別で行い、ここでは探索がエンジンに要求する機能までを範囲とする。

## 2. 前提

| 項目 | 内容 |
| --- | --- |
| ゲームエンジン | [PyBL](https://github.com/fukuchy/PyBL) |
| ルール | 戦術カードなし。補充は着手の適用時に自動で行われ、山札は1つ |
| 隠れ情報 | 相手の手札の中身と山札の順序のみ。相手の着手はすべて公開 |
| 終局結果 | 先手勝ち・後手勝ち・引き分け（両者同時の勝利条件成立、連続パスによる強制終局） |
| エージェントの入出力 | 手番プレイヤーから見える観測（Observation）と乱数生成器を受け取り、合法手を1つ返す |

## 3. 設計の決定一覧

| # | 論点 | 決定 |
| --- | --- | --- |
| 1 | ISMCTS の変種 | 素の SO-ISMCTS |
| 2 | エンジンとの境界 | determinization は PyBL の機能を使い、探索側は呼ぶ時点・視点・シードだけを決める |
| 3 | 1手の粒度 | PyBL の着手（カード×フラッグ、またはパス）をそのまま手とする。ルートの自分の手に限り、厳密に同等な手をまとめる |
| 4 | determinization の分布 | 一様ランダム（推論なし） |
| 5 | ノード構造 | 木（トランスポジションなし）。ノードは Python のオブジェクトで持つ |
| 6 | 選択方策 | availability count 付き UCB1。探索係数 c の初期値 0.7 |
| 7 | 展開 | 合法かつ未展開の手から一様ランダムに1つ。1反復1ノード |
| 8 | ロールアウト | PyBL のランダムプレイアウト |
| 9 | 報酬と逆伝播 | 勝ち 1・引き分け 0.5・負け 0 |
| 10 | 着手決定と予算 | 訪問回数最大の手を返す。予算は反復回数で指定する |
| 11 | 木の再利用・並列化 | 毎手作り直し、単一プロセスで探索する |

各決定の詳細は 4〜6 章、理由は 8 章にまとめる。

## 4. エンジンに求める機能

探索は次の機能をすべて PyBL に任せ、カードの構成や枚数の制約などのルール知識を持たない。

- 観測から、観測と矛盾しない完全情報の局面を生成する（見えないカードを、相手の手札と山札の枚数を保ったまま一様ランダムに配る）
- 既存の局面に対し、指定したプレイヤーから見えないカードだけを配り直す
- 局面の複製と上書き
- 合法手の列挙、着手の適用、手番・終局・結果の取得
- 終局までのランダムプレイアウト
- 同等手の判定に必要な観測の情報（自分の手札、見えないカードの集合、各フラッグの配置カード・確保者・先に役を完成させたプレイヤー）

乱数のシードはすべてエージェントに渡される乱数生成器から作り、同じシードの対局では同じ手を返す。

## 5. ノード

探索木は木構造とし、同じ局面に別の手順で至る場合（トランスポジション）も別のノードとして扱う。各ノードは次の情報を持つ。

| 情報 | 内容 |
| --- | --- |
| 手 | このノードに至った着手（ルートは無し） |
| 手を指したプレイヤー | 報酬はこのプレイヤーの視点で加算する。ルートは自分の相手とする |
| 親 | 親ノード |
| 子 | 着手から子ノードへの対応 |
| 訪問回数 N | このノードを通った反復の数 |
| 報酬の合計 W | 通った反復の報酬の合計 |
| 選択可能回数 A | このノードの手が合法な状態で、親から選択の候補になった回数（availability count） |

手の同一性は着手の値で判定する。同じカードを同じフラッグに出す手は、どの determinization でも同じ手として扱う。

## 6. 探索

### 6.1 1反復の流れ

着手決定の最初に、観測から局面を1つ生成して基準の局面とする。各反復は次の順に行う。

1. **determinization**: 基準の局面を作業用の局面に複製し、自分から見えないカード（相手の手札と山札）を一様ランダムに配り直す。
2. **選択**: ルートから、子が揃っているノードを UCB の値に従って下る（6.2）。
3. **展開**: 未展開の合法手があるノードに来たら、1つ展開する（6.3）。
4. **ロールアウト**: 展開した局面から終局までランダムに進める（6.4）。
5. **逆伝播**: 終局結果を、通ったノードの統計に加える（6.5）。

作業用の局面は反復のたびに基準の局面で上書きするので、ロールアウトで終局まで進めても次の反復に影響しない。

### 6.2 選択

各ノードの子の評価値を次の式で定める。

```
W / N + c · √( ln A / N )
```

- 候補は、その反復の determinization で合法な手に対応する子だけとする。
- 候補すべての選択可能回数 A を1増やしてから、評価値が最大の子に進む。
- √ の中が親の訪問回数ではなく A である点が、通常の UCT との違いである。手札の違いで、ある世界では打てるが別の世界では打てない手があるため、打てる機会があった回数で探索の度合いを測る。

### 6.3 展開

- 現在のノードで、その determinization で合法なのに子がない手が1つでもあれば、選択を止めて展開する。
- その中から一様ランダムに1つ選び、子ノードを作ってその手を適用する。1反復で展開するのは1ノードだけとする。
- 新しい子の選択可能回数 A は1で始める。これにより常に A ≥ N となる。
- 別の手札が determinize されると、展開済みに見えたノードにも新しい合法手が現れ、展開の対象に加わる。

### 6.4 ロールアウト

展開した局面から、PyBL のランダムプレイアウトで終局まで一様ランダムに進め、終局結果を得る。展開の時点で終局していれば、その結果をそのまま使う。

### 6.5 報酬と逆伝播

| 結果（そのノードの手を指したプレイヤーから見て） | 報酬 |
| --- | --- |
| 勝ち | 1 |
| 引き分け | 0.5 |
| 負け | 0 |

展開したノードからルートまでの各ノードで、訪問回数 N を1増やし、そのノードの手を指したプレイヤーから見た報酬を W に加える。確保フラッグ数の差などは報酬に加えない。

### 6.6 同等手のまとめ（ルートのみ）

ルートの自分の手について、自分の観測（手札・盤面・見えないカードの集合）の上で厳密に同等な手を1つの代表にまとめ、代表だけを探索する。観測が対称なら、一様な determinization のもとで価値も等しくなる。

**(1) フラッグの左右対称**

- 条件: すべてのフラッグ i について、フラッグ i と 8−i の両陣営の配置カード、確保者、先に役を完成させたプレイヤーが一致する（盤面全体が左右対称）。
- 成り立つとき、同じカードをフラッグ i に出す手と 8−i に出す手を同等とし、フラッグ番号の小さい方を代表とする。

**(2) 色の入れ替え**

- 条件: 2色について、すべての数字でそれぞれのカードの所在が一致する。所在とは「自分の手札」「見えないカード」「フラッグ i の自分側」「フラッグ i の相手側」のいずれかである。
- 所在の並びが等しい色どうしは同値類をなす。各同値類で色番号の最小の色を代表とし、同じ数字の代表色のカードを出す手を代表の手とする。代表のカードも自分の手札にあるので、代表の手は合法である。

**適用範囲**

- (1) と (2) は組み合わせて適用する。
- 相手の手番は determinization ごとに対称性が変わるので対象外とする。トランスポジションも扱わない。
- 主に序盤で効く。例えば初手は盤面が空なので、7枚×9本＝63通りが左右対称だけで 7枚×5種類＝35通りになる。

### 6.7 着手決定

- ルートの合法手が1つしかない場合（パスのみ等）、または同等手をまとめた結果1つになった場合は、探索せずにその手を返す。
- それ以外は指定回数の反復を行った後、ルートの子のうち訪問回数 N が最大の手を返す。同数なら平均報酬 W/N が大きい方を選ぶ。
- 返す手は代表の手そのものとする。同等な手はどれを返しても価値が等しい。

## 7. パラメータ

| 名前 | 初期値 | 意味 |
| --- | --- | --- |
| 反復回数 | 1,000（仮） | 1手あたりの反復回数。PyBL のベンチマークで速度を計測し、1手あたりの思考時間を見て調整する |
| 探索係数 c | 0.7 | UCB1 の探索係数（報酬 0〜1 前提）。原典の実験設定を確認して見直す |

計算予算は反復回数でのみ指定し、思考時間による指定は設けない。

## 8. 決定の理由

1. **SO-ISMCTS**: 戦術カードなしのルールでは相手の着手がすべて公開されるので、POM や MO-ISMCTS は不要である。相手ノードに自分の手札の情報が漏れる問題（Goodman 2019）は残るが、影響は中程度と見て実験で測る。
2. **determinization を PyBL に任せる**: C++ 実装で速く、手札と山札の枚数の整合性が保証される。指定した視点で木の途中の局面にも使えるので、RIS-MCTS に拡張できる。
3. **着手をそのまま手とする**: 補充は自動なので、選択は配置かパスだけである。同等手のまとめは自分の観測の上で厳密に成り立つものに限り、序盤の分岐を減らす。
4. **一様ランダム**: まず素の強さを測り、推論などの改良の効果を比べられるようにする。
5. **Python のオブジェクトによるノード**: 読みやすく変更しやすいので、拡張を試しやすい。速度が足りなければ配列表現や C++ に移る。
6. **UCB1, c = 0.7**: 原典どおりの方式。Exp3・Regret Matching（Lisý 2014）は確率的選択で方式が変わるので、比較実験の候補として後に回す。
7. **一様ランダムな展開**: 偏りがなく、ドメイン知識を含まない。
8. **ランダムプレイアウト**: 処理が C++ 内で完結し、反復回数を稼げる。改良の比較基準にもなる。ランダム着手による勝率推定のノイズは受け入れる。
9. **勝ち 1・引き分け 0.5・負け 0**: 対戦評価の勝率（引き分けは 0.5 勝）と一致し、探索が最大化する量と対戦で測る量がそろう。フラッグ差を加えると、勝利より多く取る手に偏る。
10. **最多訪問・反復回数指定**: 訪問の少ない手の偶然高い平均に左右されない。同じシードで同じ手を返して再現でき、マシンの速さに依存せず実験を比較できる。
11. **再利用・並列化なし**: 引き継ぐ部分木の統計は、補充後の情報集合と矛盾する世界を多く含む。エージェントは観測を受け取って手を返す形なので、木を保持するには対局開始や相手の手の検出が必要になる。Python ではスレッド並列が効かず、ルート並列化は再現性を損なう。多数対局の並列実行は評価側で対局単位に行う。

## 9. 既知の限界

- 相手ノードの統計は、常に自分の本物の手札の世界で計算される。そのため木の中の相手は、自分の手札を知っているかのように振る舞い、こちらの読みは悲観的・保守的に偏る。
- 一方で相手ノードの統計は様々な相手手札で平均されるので、木の中の相手は自分の手札をよく分かっていないかのようにも振る舞う。
- 自分が引くカードの違いもノードで区別しないので、後で引いたカードを使う手は選択可能回数を通じて間接的に扱われるだけになる。
- ランダムなロールアウトは明らかな悪手を多く含み、勝率推定のノイズが大きい。

## 10. 将来拡張

| 拡張 | 対象 | 内容 |
| --- | --- | --- |
| RIS-MCTS | 情報漏れ | 相手ノードで、相手の視点から自分の手札と山札を配り直してから選択する |
| 相手手札の推論 | determinization | 相手の着手から手札の分布を推定し、重み付きでサンプリングする |
| Exp3・Regret Matching | 選択方策 | Lisý (2014) との比較 |
| ヒューリスティックなロールアウト | ロールアウト | 役が完成する手を優先するなど |
| 打ち切り＋静的評価 | ロールアウト | 数手で止め、確保フラッグ数などで評価する |
| 価値・方策ネットワーク | 評価・選択 | Oracle Guiding（完全情報の価値で determinize 済みの葉を評価）、AlphaZero 型の選択と自己対戦学習 |
| 配列表現・C++ 化 | 速度 | v1 で正しさを確かめた後 |
